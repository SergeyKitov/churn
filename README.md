# Отток клиентов: кого удерживать завтра

<!-- Заголовок: описывает результат, а не технологию. Имя репозитория остаётся churn. -->

## Проблема

Сервис отвечает руководителю на один вопрос: кого из клиентов удерживать завтра, чтобы сохранить больше всего денег.

Ресурсы удержания (скидки, звонки) ограничены. Если раздать скидки всем, деньги уйдут тем, кто и так бы остался. Поэтому нужен список, отсортированный по ожидаемой потере в деньгах, а не просто по риску ухода.

## Решение

1. Каждый месяц делается срез клиентской базы на дату `cutoff`.
2. Модель оценивает вероятность того, что клиент не купит ничего в ближайшие N дней: p(уход).
3. LTV оценивает, сколько маржи клиент принесёт, если останется.
4. Ожидаемая потеря = p(уход) × LTV. По ней сортируется список, а порог берётся из кривой прибыли.
5. Для каждого клиента в списке выдаются три главные причины риска (SHAP). Раз в неделю приходит текстовая сводка.

RFM-сегменты нужны для EDA и как понятный бизнесу бейзлайн.

## Определение оттока

- **Дата среза** `cutoff`: признаки считаются только по транзакциям до неё.
- **Популяция**: клиенты, которые покупали хотя бы раз за N дней до `cutoff`. Давно ушедших удерживать уже поздно.
- **Метка**: 1, если за `[cutoff, cutoff + N)` нет ни одной покупки, иначе 0.
- **N** = TODO дней. Выбирается в EDA как 90-й перцентиль пауз между соседними покупками. Устойчивость проверяется на N = 60 / 90 / 120.
- **Срезы**: ежемесячные. Последний допустимый срез = конец данных − N.

## Валидация и метрики

- **Разбиение по времени (OOT)**: обучение на ранних срезах, финальный тест на последнем. Между ними зазор не меньше N, чтобы метки train не видели тестовый период.
- **Подбор параметров**: скользящие фолды по `cutoff_date` внутри train.
- **Бейзлайны**: правило «давно не покупал — уходит», затем логистическая регрессия. Основная модель — LightGBM.
- **Метрики**:
  - ROC-AUC (и Gini = 2·AUC − 1);
  - PR-AUC вместе с долей ушедших;
  - lift@10%;
  - Brier score для калибровки;
  - для всех метрик 95% бутстреп-интервалы и парный бутстреп для разницы моделей.
- **Защита от утечки**: тест, проверяющий, что признаки не меняются при добавлении транзакций после `cutoff`.

## Ограничения и риски

- **Маржа неизвестна**: в LTV она взята допущением (30%).
- **Нет данных о кампаниях**: успех удержания r и стоимость контакта c тоже допущения. Кривая прибыли считается при r = 0,1 / 0,2 / 0,3.
- **Модель предсказывает уход, а не эффект скидки**: клиент с самым высоким риском может быть уже потерян. Для проверки нужен A/B-тест на верхних децилях (дизайн описан в docs/).
- **Мало истории**: два года и около десятка срезов. OOT-тест небольшой, поэтому интервалы широкие.
- **Сезонность**: пик в ноябре сдвигает признаки. Её видно на графике PSI по месяцам.
- **Один магазин, в основном из Великобритании**: перенос на другой бизнес требует переобучения и пересмотра N.
